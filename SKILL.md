# Моделирование во Fusion 360

Здесь собран опыт работы с Fusion через коннектор `fusion`: что проверено вживую, где API
подставляет подножки и как довести деталь до печати. Подробности — в `references/`
(таблица ниже); читай нужный файл, когда задача до него дошла.

## Инструменты коннектора

| Инструмент | Для чего |
|---|---|
| `fusion_mcp_execute`, `featureType: "script"` | Выполнить Python-скрипт в Fusion — основной способ моделировать. Вывод `print()` приходит в ответе, ошибка — как `success: false` с трассировкой. Скрипту, который только читает, ставь `readOnly: true`: такой работает даже при открытом диалоге команды. |
| `fusion_mcp_read`, `queryType: "screenshot"` | Снимок вида (`direction`: front, top, iso-top-right…) — посмотреть результат глазами. |
| `fusion_mcp_read`, `queryType: "apiDocumentation"` | Поиск по справке API (`searchPattern` — имя класса, метода, свойства). |
| `fusion_mcp_read`, `queryType: "document"` | Какие документы открыты (`operation: "open"`), недавние, поиск. |
| `fusion_mcp_update` | `undo` / `redo` последней операции. |

### Второй коннектор `fusion-cad` (если подключён)

[fusion-cad-mcp](https://github.com/Mfrostbutter/fusion-cad-mcp) (бета) работает поверх того же
Fusion и даёт ~75 готовых команд **в миллиметрах**: `create_sketch`, `add_rectangle`, `extrude`,
`add_hole`, `bounding_box`, `audit_feature_health`, `export`, справочник `find_gotcha` и др.
Удобен для простых построений и быстрых проверок. Сложные операции и нестандартный анализ —
скриптом через `fusion` (для чтения — с `readOnly: true`).

Все правила ниже (активный документ, один чат за раз) действуют и для него: Fusion тот же.
**Единицы разные:** у команд `fusion-cad` — мм, в скриптах API — см (правило 3). Не переносить
числа между ними без перевода.

Проверено 12.10.2026 (Fusion 2705.1.25):
- Смотри на `result`, а не только на `ok`. Пример: `export` скрытого тела вернул `ok: true` и
  `bytes_written: 0` — файла нет.
- `add_hole` с `extent_kind: "all"` (насквозь) падает (`InternalValidationError :
  logicalSelection`); с `extent_kind: "distance"` и `depth_expression` — работает и оставляет
  в истории эскиз `_hole_position_helper`. Не удаляй его: на его точке держится положение
  отверстия.
- `execute` передаёт скрипт как есть и после кода вызывает `run()` (вывод из `run()` пришёл) —
  правило 1 (своя `run()`, вывод латиницей) обязательно.

## Главные правила

### 1. Скрипт — всегда функцией `run()` и с выводом латиницей
- Весь рабочий код пиши внутри `def run(_context: str):` (шаблон — сниппет 1 в
  `references/snippets.md`). Коннектор помнит функции между запусками: без своей `run` после
  твоего кода выполнится **чужая** `run` из прошлого скрипта (например, из другого чата) и
  что-то сделает с активным документом.
- Исключение в скрипте **откатывает все его изменения**. Смотри на `success`, а не только на
  напечатанный текст.
- Кириллицу в выводе коннектор портит. Печатай по-английски, русские имена — через `ascii(...)`.
  Портит и русские **строки в коде** (пути, имена компонентов): такой скрипт держи файлом на
  диске и запускай коротким скриптом
  `g = {'__name__': 'x'}; exec(open(r'<латинский путь>.py', encoding='utf-8').read(), g); g['run']('')`,
  либо задавай имена UTF-8 hex (`references/api-pitfalls.md`, раздел 0).

### 2. Сначала — какой документ активен
Скрипты работают с **активной вкладкой** Fusion. Если пользователь переключил вкладку, открыл
второе окно или другой чат параллельно управляет Fusion, скрипт молча изменит не тот документ.
Это уже случалось: реверс-инжиниринг сбился из-за второго окна, а тестовый документ одного чата
стал активным в другом.
- В начале работы — `fusion_mcp_read` → `document` / `open`; в каждом изменяющем скрипте
  печатай имя активного документа и что в нём лежит (шаблон сниппета 1).
- Документ не тот или в нём что-то неожиданное (новые шаги истории, чужие тела) — остановись
  и спроси пользователя, не переключай молча.
- Fusion должен управлять один чат за раз.
- Новый документ создавай только с согласия и в конце скажи, какая вкладка теперь активна.

### 3. Единицы: внутри API — сантиметры
Документ показывает мм, но API везде считает длины в **см**, углы — в **радианах**. 50 мм = `5`.
(Исключение — команды коннектора `fusion-cad`: они в мм, см. выше.)
- Размеры для операций задавай строкой с единицами: `ValueInput.createByString('50 mm')`.
- В `Point3D.create(...)` напрямую — только см. Удобнее помощник `P(x, y, z)` в мм из сниппета 1.
- `boundingBox`, `volume`, `userParameters[...].value` — тоже в см; пользователю показывай мм.
- Число больше 50 прямо в `Point3D.create` — это полметра; почти наверняка забыт перевод.

### 4. Оси эскизов не угадывай
На плоскостях XZ и YZ ось эскиза, идущая вдоль мировой Z, смотрит в **−Z** (проверено; таблица
в `references/coordinates.md`). На грани детали оси эскиза вообще произвольные. Поэтому точку
для эскиза получай из мировой: `sketch.modelToSketchSpace(p)`, обратно — `sketchToModelSpace`.
После операции сверяй габарит тела с тем, что ожидал.

### 5. Параметрически и с именами
- Ключевые размеры — в `design.userParameters` (единицы `'mm'`), в операциях — выражения вроде
  `'wall * 2'`. Пользователь потом правит их в Modify → Change Parameters.
- Давай имена компонентам, эскизам, операциям и телам: по имени потом легко найти (`itemByName`),
  и дерево понятно пользователю.
- Грани и рёбра выбирай **по геометрии** (нормаль, центр, тип кривой), а не по номеру: номера
  меняются после каждой операции.

### 6. Ничего не разрушать
- Не удаляй, не сохраняй и не закрывай документы без согласия.
- Исходник (скан, импорт) можно переименовать и спрятать, но не удалять и не менять его
  геометрию — работай с копией.
- Временные изменения вида (цвет, видимость, положение компонента, камера) возвращай как было.
  После смены положения компонента проверь `design.snapshots.hasPendingSnapshot` — иначе в
  истории появится лишний шаг «Position».
- Операция пошла не так — откати через `fusion_mcp_update` `undo`.
- Крупную добавку сначала строй отдельным телом, проверь, потом объединяй (Combine).

### 7. Проверяй после каждого шага
После каждого изменяющего скрипта печатай и сверяй с ожиданием (сниппет 2 «Отчёт о состоянии»):
- габарит в мм, число тел и оболочек (одно сплошное тело = 1 shell), объём;
- все шаги истории здоровы (`healthState`);
- при сомнении — `screenshot` с нужной стороны. Какой вид коннектор считает «front» или «top»,
  зависит от настройки «Y up / Z up» в документе — сверяй ракурс по картинке;
- деталь стыкуется с другой (штырь–гнездо, байонет, крышка) — проверь **зазоры посадки**
  отдельно: проверка пересечений не замечает касания «впритык». Порядок — `print-export.md`,
  «Проверка посадок» (сниппет 16).
Перед экспортом — поиск микрограней (сниппет 7), после экспорта — `check_stl.py`
(`references/print-export.md`).

### 8. Файлы между Fusion и Claude
Fusion не видит служебные папки приложения Claude (`AppData\Roaming\Claude\...`): запись туда из
скрипта падает с FileNotFoundError. Для обмена бери папку проекта пользователя (например, `C:\Projects\<имя>\`) или
`%TEMP%\fusion_work` (переменная `WORK` в сниппете 1). Пути держи короткими: Windows
ограничивает путь 260 символами.

### 9. Сверяй API, прежде чем писать
Незнакомый метод — сначала `apiDocumentation`. Известные ловушки собраны в
`references/api-pitfalls.md`. Получил AttributeError — не угадывай второй раз, посмотри справку.

## Порядок работы над деталью

1. Уточни назначение и размеры или предложи разумные и скажи, какие взял. Для печати — принтер
   и материал.
2. Для заметной работы покажи план простыми словами и дождись одобрения.
3. Проверь активный документ (правило 2). Деталь строй в отдельном компоненте.
4. Параметры → базовый эскиз → выдавливание / вращение → вырезы и отверстия → скругления и
   фаски → оболочка (Shell) последней. Порядок важен: скругления до вырезов часто ломаются,
   Shell до вырезов даёт неправильную геометрию. (Полость можно сделать и не Shell, а вырезом по
   внутреннему контуру — тогда она идёт раньше; так строятся корпуса по скану.)
5. Проверка после каждого шага (правило 7), в конце — screenshot с одного-двух ракурсов.
6. Экспорт, если нужен (`references/print-export.md`).
7. Отчёт: что построено, размеры в мм, какие параметры можно менять, как проверить самому
   (что открыть в дереве, Inspect → Measure). Напомни про **Ctrl+S**: документ сам не сохраняется.

## Программы в `scripts/`

Запускаются **вне Fusion**, обычным `py`. Папка программ (дальше — `<scripts>`):
`C:\Users\<пользователь>\.claude\skills\fusion360-modeling\scripts\` (то же, что
`~/.claude/skills/fusion360-modeling/scripts/`). Указывай полный путь: текущая папка обычно другая.
- `scan_tools.py` — анализ скана: `info`, `matrix`, `section`, `planes`, `compare`;
- `check_stl.py` — проверка STL перед печатью;
- `render_video.py` — видео-презентация модели (и совмещения со сканом).

Нужны numpy и Pillow, для видео ещё imageio и imageio-ffmpeg. Проверка:
`py -c "import numpy, PIL, imageio, imageio_ffmpeg"`. Если чего-то нет — спроси разрешения на
установку (`py -m pip install numpy pillow imageio imageio-ffmpeg`).
