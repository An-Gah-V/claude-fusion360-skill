# Картинки и видео модели

## Что выбрать

| Нужно | Способ |
|---|---|
| Быстро посмотреть результат самому или показать пользователю | `fusion_mcp_read` → `screenshot` (`direction`: front, top, iso-top-right…) |
| Картинка с точным ракурсом и размером | сниппет 12 (`snippets.md`): камера + `saveAsImageFile` |
| Ролик или картинки, где **детали двигаются** (инструкция по сборке, разнесённый вид), фото для карточки товара, а также **простой облёт модели** | Custom Graphics во Fusion + сборка кадров на Python — раздел «Ролик с движением деталей» (быстрее и красивее numpy-рендера) |
| Видео со **сканом** (облёт, «схождение» скана с моделью) | `scripts/render_video.py` вне Fusion (умеет и облёт без скана — запасной вариант, если Fusion недоступен) |

## Почему скан — не кадрами Fusion

Проверено в проекте: сетку скана без текстуры Fusion рисует бледной, почти прозрачной, а цвет
и прозрачность сетки меняются с оговорками (нужен прокси, см. `api-pitfalls.md`). Поэтому кадры
со сканом рисует `render_video.py` на numpy: модель — треугольниками из STL, скан — его точками;
склейка в MP4 через imageio.

Для обычных тел (B-rep) это не так: кадр Fusion через Custom Graphics быстрый (~0.15 с) и
красивый — см. «Ролик с движением деталей».

## Видео со сканом (`render_video.py`)

1. Проверь библиотеки: `py -c "import numpy, PIL, imageio, imageio_ffmpeg"`. Нет — спроси
   разрешения: `py -m pip install numpy pillow imageio imageio-ffmpeg` (ffmpeg приходит внутри
   imageio-ffmpeg, в систему ничего не прописывает).
2. Экспортируй модель в двоичный STL с `MeshRefinementLow` или `Medium` — отдельным файлом,
   не тем, что для печати. Каждый треугольник рисуется отдельно: 2 тыс. треугольников — быстро,
   больше 50 тыс. — медленно (скрипт предупредит).
3. Для «схождения» нужен скан в тех же осях, что и модель: выгрузи **выровненную** сетку
   (сниппет 9) — папку с `pts.f32` / `nrm.f32`.
4. Пробные кадры (`<scripts>` — папка программ скилла, см. SKILL.md):
   ```
   py <scripts>\render_video.py --stl part.stl --scan <папка скана> --out C:\Projects\<имя>\presentation.mp4 --test --title "Корпус датчика" --deviation "отклонение ≈ 0,2–0,3 мм" --final "Готово к печати · STL + STEP"
   ```
   Кадры лягут рядом с видео: `presentation_test_NNN.png`. Посмотри их (Read): деталь целиком в
   кадре, подписи читаются?
5. Полное видео — тот же запуск без `--test`, **в фоне**. Время (замерено): со сканом 2 млн точек
   ~1–2 с на кадр, 372 кадра (15.5 с видео) ≈ 6–12 мин; без скана, модель ~2 тыс. треугольников —
   192 кадра (8 с) ≈ 1 мин.
6. Проверь готовый файл: размер, открывается ли (можно вытащить пару кадров через imageio).

Сюжет со сканом (15.5 с): модель поворачивается → синий скан влетает сбоку и садится на модель →
облёт с полупрозрачным сканом → скан растворяется. Без `--scan` — плавный облёт на 360° (8 с).

### Если меняешь render_video.py

Код уже прошёл ревью. Известные ловушки, которые там исправлены:
- z-буфер точек: для каждого пикселя явно брать ближайшую точку (`lexsort` + «первая в группе»),
  а не записывать в несколько проходов — иначе дальняя сторона просвечивает «зерном»;
- глубину внутри треугольника интерполировать как `1/z` (перспектива), а не `z`;
- заполнение пустот — через `np.pad`, а не `np.roll` (иначе края кадра «заворачиваются»);
- прозрачность менять плавно (0.5 с), без скачков между сценами;
- шрифты загружать один раз, а не в каждом кадре.

## Ролик с движением деталей (инструкция по сборке, карточка товара)

**(проверено 24.10.2026)** Вертикальный ролик-инструкция 1080×1920, 43 с, 30 к/с (1290 кадров)
для разборной детали из 5 тел: детали разъезжаются, опускаются, пружинный ключ «сжимается»,
сменная вставка выходит и встаёт на место. Плюс картинка-инфографика 900×1200 и главное фото
1200×1600 из тех же рендеров.

### Схема

Три программы вне Fusion и три модуля, которые выполняются внутри Fusion. В скилле их нет —
пиши их в папке проекта по описанию ниже (имена условные):

| Где | Что | Задача |
|---|---|---|
| вне | `make_spec.py` | **сценарий**: для каждого кадра камера (цель, азимут, высота, расстояние), смещение и прозрачность каждой детали, подсказки, подписи сцен → JSON |
| внутри | `setup_fusion.py` | запомнить исходный вид в JSON, построить Custom Graphics из тел, спрятать настоящие тела и папки |
| внутри | `render_fusion.py` | для кадров `a..b-1`: двигать графику, ставить камеру, сохранять PNG с прозрачным фоном |
| внутри | `restore_fusion.py` | удалить графику, вернуть видимость, стиль и камеру, **удалить файл состояния** |
| вне | `compose.py` | фон + кадры + подписи + переходы → MP4 (imageio-ffmpeg, H.264) |
| вне | `infographic.py` | картинка из отдельных «стоп-кадров» с подписями |

Модули внутри Fusion держи файлами в проекте и запускай коротким скриптом — как в
`api-pitfalls.md`, раздел 0, **обязательно внутри своей `run`** (иначе коннектор вызовет чужую):

```python
def run(_context: str):
    g = {'__name__': 'x'}
    exec(open(r'<папка проекта латиницей>\render_fusion.py', encoding='utf-8').read(), g)
    print('rendered', g['render'](0, 330))
```

### Custom Graphics вместо движения тел

Двигать настоящие тела или компоненты ради кадров нельзя: в истории появятся шаги Move /
Position. Временная графика (Custom Graphics) в историю не попадает и `hasPendingSnapshot` не
трогает.

```python
grp = root.customGraphicsGroups.add(); grp.id = 'INSTR'          # по id потом найти и удалить
calc = body.meshManager.createMeshCalculator()
calc.setQuality(adsk.fusion.TriangleMeshQualityOptions.NormalQualityTriangleMesh)
m = calc.calculate()                                              # ~10–20 тыс. треугольников на тело
mesh = grp.addMesh(adsk.fusion.CustomGraphicsCoordinates.create(m.nodeCoordinatesAsDouble),
                   m.nodeIndices, m.normalVectorsAsDouble, m.nodeIndices)
mesh.id = 'part1'
mesh.color = adsk.fusion.CustomGraphicsBasicMaterialColorEffect.create(
    diffuse, ambient, specular, emissive, 20.0, opacity)          # Color.create(r,g,b,255); opacity 0..1
# каждый кадр:
mx = adsk.core.Matrix3D.create(); mx.translation = adsk.core.Vector3D.create(dx, dy, dz)  # см
mesh.transform = mx; mesh.isVisible = opacity > 0
```

- Белая деталь на тёмном фоне: diffuse ≈ (235, 235, 232), ambient ≈ (90, 90, 90), specular ≈
  (60, 60, 60), emissive ≈ (25, 25, 25). Акцентная деталь (инструмент, сменная часть) — цветом,
  с emissive и ambient ≈ 0.45 и 0.35 от цвета, иначе в тени она сереет.
- Прозрачность задаётся только при создании цвета: для плавного появления присваивай
  `mesh.color` заново в кадре, где она поменялась (запоминай последнее значение, чтобы не
  создавать цвет каждый кадр).
- Одно тело — несколько сеток: та же сетка под разными `id` даёт копии детали (например,
  запасные части в кадре «комплект»).
- Деформация (пружинный ключ сжимается): пересоздавай сетку с повёрнутыми вершинами и
  нормалями. У небольшой детали сетка маленькая (ключ — ~230 треугольников), это мгновенно;
  исходную сетку сохрани в JSON при подготовке. Ось поворота и границу подвижной части
  держи именованными константами: они привязаны к положению тела в модели.
- Кольцо-подсказка вокруг отверстия: тор, сгенерированный списками (numpy внутри Fusion нет),
  «приклеенный» к детали тем же `transform`.
- `vp.visualStyle = adsk.core.VisualStyles.ShadedVisualStyle` — без рёбер, чище.
- Перед кадрами спрячь тела (`isLightBulbOn = False`) и папки (`root.isConstructionFolderLightBulbOn`,
  `isSketchFolderLightBulbOn`, `isOriginFolderLightBulbOn`), иначе плоскости и эскизы попадут в кадр.
- Если кадр показывает узел крупно и его плохо видно (белое на белом, ракурс прячет движение),
  выдели инструмент цветом и выбери ракурс, где движение идёт поперёк взгляда (например, сжатие
  ключа — сверху-сзади, а не сбоку).

### Сохранение кадра

```python
o = adsk.core.SaveImageFileOptions.create(путь)
o.width, o.height = 1080, 1920; o.isBackgroundTransparent = True; o.isAntiAliased = True
vp.saveAsImageFileWithOptions(o)
```

- **Скорость ~0.13–0.15 с на кадр** 1080×1920 (сцена ~35 тыс. треугольников).
- Пропорции кадра могут не совпадать с окном Fusion: кадр строится по вертикальному углу
  обзора камеры. Угол задавай явно, камеру назначай дважды — `api-pitfalls.md`, раздел 8.
- Фон прозрачный → в Python накладывай на любой фон (`Image.alpha_composite`).

### Партии и защита от старых кадров

- **Не больше ~330 кадров за вызов** (≈ 45 с). Партия 470 кадров не дождалась ответа коннектора
  (`The operation timed out`), хотя Fusion дорисовал её до конца — проверяй файлы на диске,
  а не ответ.
- Сценарий кладёт в JSON «отпечаток» только того, что рисует Fusion (камера, детали, подсказки, без
  подписей): `sha256(json.dumps(..., sort_keys=True))`. Рендер пишет его рядом с кадрами
  **после партии с последним кадром**; сборщик видео отказывается работать при несовпадении.
  Так правка подписей не требует перерисовки, а изменение движения не даст тихо собрать ролик
  из старых кадров. Слабое место: если ранние партии рисовались по старому сценарию, а
  последняя — по новому, отпечаток совпадёт. Надёжнее писать отпечаток по каждой партии
  (`_hash_<a>.txt`) и сверять все; минимум — рендерить все партии подряд по одному сценарию.
- Пробные кадры — в **отдельные** файл сценария и папку. Иначе 10 пробных кадров лягут под
  именами `f_00000…f_00009` поверх кадров ролика, и сборщик этого не заметит.
- «Стоп-кадр» (инфографика, фото для карточки) — тот же рендер со своими `name`, `w`, `h` у
  кадра и своей папкой вывода в сценарии.

### Подготовка и возврат вида

- Состояние вида (видимость тел, папки, стиль, камера) пиши в JSON **только если файла ещё нет**,
  а после возврата файл удаляй. Иначе следующий запуск вернёт устаревший вид.
- **Сначала проверь, что активна нужная вкладка** (нужные тела существуют), и только потом пиши
  файл состояния: исключение откатывает изменения модели, но не файлы на диске — однажды так
  записалось состояние чужой вкладки.
- Пока идёт рендер, пользователь не должен трогать Fusion: скрипт управляет камерой активного окна.

### Сборка кадров (вне Fusion)

- Подписи — на **тёмной полосе** (сплошная сверху, плавно уходит в прозрачность): иначе светлая
  деталь, зашедшая в верх кадра, съедает текст. Высоту полосы считай по самой длинной подписи.
- Шрифт под телефон: в вертикальном 1080×1920 заголовок ~76 px, пояснение ~52 px, не больше
  3 строк; на картинке 900×1200 пояснения не меньше ~24 px (на экране телефона она ужимается
  примерно вдвое). Переносы проверяй скриптом, картинку — глазами.
- Склейки между далёкими ракурсами — затемнением слоя модели (~0.35 с), смена подписей —
  плавно (~0.4 с).
- Атмосферный фон можно сгенерировать нейросетью (тёмный, почти однотонный, без объектов в
  центре), затем размыть и чуть затемнить. Саму деталь нейросетью не рисуй: узор, пропорции и
  мелкие элементы выйдут неверными, а для инструкции это недопустимо.
- Кодирование: `imageio.get_writer(путь, fps=30, codec='libx264', macro_block_size=8,
  ffmpeg_params=['-crf', '18', '-pix_fmt', 'yuv420p', '-movflags', '+faststart'])` — 1080 делится
  на 8, размер не меняется. Готовый файл проверяй, вытащив несколько кадров через
  `imageio.get_reader`.
- Тексты отдай на проверку: в инструкции легко пропустить «где именно» (какие отверстия,
  какая сторона), шаги без условий («сначала снимите…») и обещания комплектации.

## Временные изменения в Fusion ради кадров

Если для кадров меняешь цвет, видимость или камеру — запомни исходное и верни. Положение
деталей для кадров меняй только через Custom Graphics (раздел выше). Если всё же сдвигал
компонент — верни матрицу и проверь `design.snapshots.hasPendingSnapshot == False`: иначе в
истории появится шаг «Position». Назначенный для кадра внешний вид убери, чтобы тело вернулось к цвету компонента.
